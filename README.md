# ExamGuard — 시험장 무선기기 탐지 보조 앱

감독관 휴대폰 한 대로 숨긴 이어폰·스마트안경·휴대폰이 있을 가능성이 높은 **자리**를 알려 주는 오픈소스 앱입니다.
학교·자격 시험장의 공정성을 위해 공익 목적으로 공개하며, 상용 판매하지 않습니다. (MIT License)

> 결과는 "확인할 자리"를 알려 주는 참고값입니다. 점수만으로 응시자를 처분하지 말고, 반드시 감독관이 직접 확인하세요.

- 시연 페이지: [`index.html`](index.html) (브라우저로 열면 80초 시연이 반복 재생됩니다. 화면 속 데이터는 시뮬레이션입니다)
- 시연 영상: [`docs/ExamGuard_demo.mp4`](docs/ExamGuard_demo.mp4)
- 앱 코드: [`lib/main.dart`](lib/main.dart) (Flutter, Android + iOS, 한 화면 구성)

## 패턴 분석 — 신호 세기로 자리 찾기

감독관이 모든 통로를 지나가면, 교실 안 기기는 반드시 1m 안쪽으로 한 번 이상 지나갑니다. 이 사실을 이용합니다.

1. **원거리 제외:** 최대 세기가 근거리 기준(−65dBm, 조절 가능)보다 약하면 먼 기기로 보고 분석하지 않습니다.
2. **위치 추정:** 강하게 잡힌 지점일수록 무게를 크게 둔 가중 평균으로 기기 위치를 구하고, 켜진 자리 중 가장 가까운 자리에 배정합니다. 한쪽 통로에서만 강하게 잡혔으면 `B-2/3`처럼 두 자리를 함께 표시합니다.
3. **근접 피크 (25%):** 최대 세기. −40dBm에 가까울수록 높습니다.
4. **거리-세기 일치도 (25%):** 추정 위치에 가까워질수록 세지는지(로그 거리와 RSSI의 음의 상관).
5. **세기 변화폭 (20%):** 최대 − 하위 20% 세기. 가까운 기기는 15~30dB 출렁이고, 벽 너머 공유기는 작습니다.
6. **반복 피크 (15%):** 근접 통과 구간마다 최고점 위치를 모아, 여러 바퀴에서 같은 자리(1m 이내)인지 봅니다.
7. **지속성 (15%):** 최근 3분 중 신호가 잡힌 10초 구간 비율.
8. **종류 가중치:** 이어폰·안경 1.0, 폰·핫스팟 0.9, 워치 0.7, 미확인 0.4를 곱합니다.

가상 교실 시뮬레이션(`tools/sim.py`) 결과: 귓속 이어폰(B-3) 88점·자리 정확, 가방 속 폰(D-1) 72점·자리 정확, 벽 너머 옆 교실 폰 최대 −72dBm → 원거리 제외, 복도 공유기 23점.

## 한계와 보완

| 한계 | 앱의 보완 | 남는 한계 |
| --- | --- | --- |
| 전원이 꺼진 기기, LTE로만 통신하는 장치 | 입실 점검(자기장)으로 5cm 안 근접 확인. 이어폰과 연결된 숨긴 폰은 BLE를 계속 내보내므로 폰 쪽을 탐지 | 순찰 중 원거리 탐지는 불가. LTE 송신 자체는 휴대폰으로 볼 수 없음 |
| 이미 연결된 블루투스 통신 내용 | 통신 내용 대신 연결 상대 기기의 광고 신호와 위치를 탐지 | 통신 내용은 볼 수 없고 보지도 않음 |
| iOS Wi-Fi 스캔 불가 | BLE만으로 동작하도록 설계. 고사장마다 안드로이드 폰 한 대를 쓰면 핫스팟까지 탐지 | iOS 단독으로는 핫스팟 탐지 불가 |
| BLE 주소 랜덤화(약 15분마다 변경) | 광고 패킷 지문 + 이전 주소 소멸 2~30초 안 + 세기 ±10dB 조건으로 같은 기기 병합 | 같은 기종이 같은 자리에 붙어 있으면 잘못 병합될 수 있음 |
| 걸음 추적 오차 누적 | 통로 스냅, 방향 축 보정, U턴 자동 재보정, 탭 보정 | 통로를 벗어나 대각선으로 걸으면 정확도 저하 |
| 걸음 기준·보폭·경고 점수 보정 | 걸음 기준은 최근 흔들림으로 자동 조정, 보폭은 [보폭 보정]으로 자동 계산, 경고 점수·근거리 기준은 슬라이더 | 고사장마다 첫 회차에 한 번 확인 권장 |

## 설치와 빌드

이 저장소에는 `lib/main.dart`, `pubspec.yaml`, 권한 설정(`android/app/src/main/AndroidManifest.xml`, `ios/Runner/Info.plist`)이 들어 있습니다. 나머지 플랫폼 파일은 Flutter가 만들어 줍니다.

```bash
git clone https://github.com/sehunkim-naeum/ai-cheating.git
cd ai-cheating
flutter create --org ai.naeum --platforms android,ios .   # 없는 플랫폼 파일만 생성, 기존 파일은 유지
flutter pub get
flutter analyze
```

1. `android/app/build.gradle`(또는 `build.gradle.kts`)의 `minSdkVersion`을 21 이상으로 설정합니다.
2. Android: `flutter build apk --release` → APK를 감독관 폰에 바로 설치합니다.
3. iOS: Xcode에서 서명 후 TestFlight로 배포하면 기관 내부 설치가 가능합니다.
4. 실제 교실에서 한 번 시험 운용하며 근거리 기준·경고 점수를 확인하세요.

## 현장 사용 순서

1. **설정:** 고사장 이름, 행·열, 책상 간격 입력. 빈자리는 맵의 책상을 탭.
2. **기준 등록:** 응시자 입실 전 빈 교실에서 [기준 등록] (15초).
3. **입실 점검(선택):** 출입구에서 [입실 점검] → 폰을 귀·안경·주머니 5cm까지 대 보기.
4. **보폭 보정 후 시작:** 교탁 쪽 왼쪽 앞 모서리(원점)에서 폰을 교실 뒤쪽으로 향하고 시작 → 첫 통로 끝에서 [도착].
5. **순찰:** 통로를 따라 천천히 1~2바퀴. 통로 끝에서 U턴하면 자동 재보정, 위치가 어긋나면 맵을 탭.
6. **확인:** 빨간 배너의 자리를 조용히 확인.

## 개인정보와 윤리

- 주변 기기가 공개로 내보내는 광고 신호만 수신하며, 연결하거나 통신 내용을 가로채지 않습니다.
- 데이터는 폰 안에만 있고 서버로 보내지 않으며, 중지하면 지워집니다.
- 탐지 결과만으로 처분하지 않도록 운영 규정에 명시하세요.
